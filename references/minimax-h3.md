# MiniMax H3 调用

本项目直接使用已审阅的中文结构提示词。角色引用、机位、动作时间轴、人声和同步字幕逐项保留，接口的 prompt 字段使用这份原文。MiniMax 通道沿用同一份故事和表演设计。

## 图片与参数

每个 @图片N 对应本次真实传入的第 N 张图片。按提示词顺序提交，记录角色编号、文件路径和哈希。角色参考图只控制人物身份和服饰，多视图板的版式属于参考素材。

AutoDL 工作流按其实际参数填写 ref_image_0、ref_image_1 等字段，分别对应 @图片1、@图片2。当前已验证本地图片可编码为 data:image/png;base64 后提交。只提交本次需要的角色或场景图片。

时长、分辨率和画幅分别写在接口参数中。按本集分镜在10–15秒内选择时长，默认768p、1:1。直连传 768P，AutoDL 使用工作流支持的 768p(1:1)。付费生成前核对实际通道及分辨率，用户已明确指定时按指定执行。无法使用已确认档位时先征得用户同意。

## 人声与字幕

按[对白贯穿全场](storyboard.md#对白贯穿全场)安排开场、中段推进和收尾的角色开口，逐句写明谁开口、具体台词、语气和起止时间。对白属于画内人物时，镜头让该人物的脸和口型清楚可见。画外声及内心OS确有叙事用途时，明确声源与人物是否开口。

每句台词配「画面底部出现字幕，字幕内容为“台词原文”，字幕需与音频节奏完全同步。」替换为实际原文，保留标点。使用中文的声音要求，说明无BGM，现场音和角色声音按本集安排保留。

短片的人声需给每句单独的发音时段，并在说话时保持说话人的脸与口型可见。句子只由指定角色说一次，其他人物的反应交给动作和表情。把同一句话反复写进动作段、人声段和旁白容易造成重复或多余人声，正文按本次设计保留一份台词及其同步字幕要求即可。字幕内容的重复用于指定画面文字，不意味着再朗读一遍。

修订声音问题时优先缩短过长的宣读句，给开口前和收音后留空隙。转折依赖一个“不”字等弱读词时，可在用户要求重写台词的范围内改成语义明确的肯定表达，并把改动交给用户审阅。以上是执行改进，不能宣称已经通过新视频验证，也不能因改稿自动提交付费重做。

## 镜头、台词与字幕绑定

本节仅适用于 MiniMax H3 渠道（含 AutoDL H3）。同段绑定、说完再切、减少额外文字及后期字幕备选均为 MiniMax 专项处理，不应用于器灵 Seedance、宿主 Seedance 或其他 Seedance 生成方式。后期字幕仍是须用户明确选择的备选，本次范围确认不代表启用该方案。

沿用中文结构提示词，将每个镜头的角色、可见动作、逐字台词和对应字幕放在同一段。台词在模型提示词中只作为发声指令出现一次；字幕原文是文字要求，不是第二次发声。独立对白表如需审阅，放在制作说明中，不再作为另一套时间轴重复提交。此规则是本通道对通用分栏模板的细化。

- 每个发声段明确角色姓名及稳定外观、声音特征，并说明此刻谁开口、谁闭口聆听。默认一句说完、当前字幕消失，再切换到下一说话人的镜头；保留自然的接话和反应，不把对白集中到局部。
- 同时写清时间和可见事件，例如“递书时开口，最后一个字说完后收口，官吏接稳书简，当前字幕消失，随后切入殿内”。不能只靠秒数把独立台词表与镜头关联。
- 每句字幕就近写明原文、开始和结束条件，底部仅显示当前句，随发音逐字同步。非叙事必需的片头标题、人物介绍和可读道具文字不额外安排；不堆叠长串禁止文字的负面提示。
- 在句末保留自然收音与切镜余量；镜头内不一边让角色说关键台词，一边切去难以判断声源的道具特写。是否需要跨镜头人声在审阅稿明确设计，不能把意外字幕串镜头当作艺术处理。

上述安排用于减少绑定歧义，不保证模型严格执行时间或正确绘制汉字。模型生成字幕的错字、出现时机与人声完整性分别验收。自动转写漏词仅记为疑点，不直接判定原声漏说；以实际听检核对角色、逐字内容和起止时间，转写或强制对齐不能证明模型说出了预定原文。

### 2026-11-06 核查与方案边界

本地先前优化已包含缩短长句、指定说话人和时间、避免重复发声，但没有通过新视频验证的结论。新反馈显示仅这些要求还不足以保证字幕与角色对应，因此优先补上同镜头内的事件绑定。

核查来源：
- [ComfyUI H3 提示词指南](https://github.com/Comfy-Org/docs/blob/main/tutorials/video/minimax/minimax-h3-prompt-guide.mdx)：对白放在所属镜头内，多说话人参考音频可能串角色，建议绑定可见事件；文档方案不是对实际生成的保证。
- [MiniMax 官方基础指南](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)：提供稳定说话人标识、对白和画面文字的分离表示。其专用标签与英文结构不同于本项目已确认的中文格式，不能自动转换或宣称两者等效。
- [MiniMax H3 issue 95](https://github.com/MiniMax-AI/MiniMax-H3/issues/95)：独立参考音频引发额外、重复或开头缺音节的用户报告，作者注明缺乏保留的异常视频与已执行的完整复现；不能据此断言本地无参考音频任务同因，也不把外部配音作为必然修复。
- [ComfyUI issue 15454](https://github.com/Comfy-Org/ComfyUI/issues/15454)：多说话人声音／口音串扰报告，涉及 FL2VA 与 Ref2VA；不等于本地字幕错位的已证实根因。

更强的字幕控制备选是先生成角色对白与干净画面，再按听检确认的实际原声时间用 FFmpeg 排字幕。它可控制排出的字形和时间，但不能修复漏说、串角色或错误口型，也不保证模型真的不生成文字。此方案改变当前“模型同步生成字幕”的约定，仅在用户明确选择后启用；已有烧入画面的错字不能靠叠一套新字幕冒充修好。改用官方标签、外部配音或分段生成同样先说明变化，不自动切换，也不自动付费试验。

本节是待验证方案；用户授权验证时先定一个变量、保存审阅原文与真实任务，保留所有结果。质量失败或结果不明按既有规则处理，不自动追加对照或重试。

## 生成阶段的配乐控制

2026-11-05核查了MiniMax官方H3提示词指南、V2创建接口和AutoDL两个H3工作流的实时输入参数。H3同时生成画面与声音，已检查的接口未公开“只关闭背景音乐、保留对白和音效”的独立开关。AutoDL纯文工作流当前只公开prompt、duration、resolution和seed。多参考工作流的ref_audio字段用于参考音频，空白音频默认值不能当作关闭配乐的保证。实际工作流变化时重新核查，不能自行添加bgm=false、music=false、negative_prompt或把其他接口的generate_audio字段移植过来。

官方提示词指南区分现场声音和观众听到的配乐，在无配乐时将提示词中的non_diegetic_music写为N/A。这是提示词写法，并非HTTP接口参数，也没有提供对任意生成结果都无音乐的保证。这里记录官方方法供核对，实际提交仍遵循本项目已确认的中文结构。

中文提示词把现场声音、人声和背景配乐分别表达。逐句对白、语气、时间及同步字幕继续按文稿填写。声音要求可写为：

```text
【现场声音】
石地脚步、衣料摩擦、空粮袋抖动、工具落石声，与各自发生的动作同步。人物停顿时，只留下低弱的院落环境底噪。

【人声】
按本集既定说话人、逐字台词和时间开口，保留对应底部同步字幕。

【背景配乐】
无。全片没有画外旋律、弦乐、鼓点和音乐铺底。声音由本条已列明的现场声与人物人声组成。
```

这份中文示例是待验证的表达方案，不能宣称与官方字段逐项等效或已解决配乐问题。视觉中的戏曲身段、纸张质感、快切和强动作只用于画面设计，不据此添加乐器、锣鼓或配乐。声音段落中的“节拍”“重音”等词尽量落实为具体物体的接触声，降低含糊指令带来的歧义，此点属于实践推断。

新声音要求须在下次文稿审阅时可见，接口仍原文提交。不自动改写已经审阅、已经提交或已经生成的历史作品。生成后分别核对人声、现场声和配乐，音乐检测仅为提示，疑点保留待听检。修改规则本身不触发付费测试；付费重做按项目要求取得该次明确同意后执行。

核查来源：[MiniMax官方提示词指南4.6与4.7](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)、[MiniMax V2创建接口](https://platform.minimax.io/docs/api-reference/video-generation-v2-create)、[AutoDL H3纯文工作流](https://www.autodl.art/large-model/comfyui/minimax_h3_lightx2v_no_pic)。

## 保存与提交

分镜提示词.md、可复制提示词.txt与JSON中的prompt_template内容一致。提交时直接读取已审阅文本。保存请求摘要与真实任务号，先查原任务再恢复下载。

用户要求自己检查时，取得文件后交付原片。用户反馈问题时先定位具体分镜并修改文稿，新的付费重做必须获得用户针对该次生成的明确同意。
