# 分镜与视频提示词

这是第二步。读取第一步选定的事件与精彩片段，生成的同一份完整提示词可用于接口或宿主内置videogen，也可交给用户在豆包等工具中手动生成。默认10秒、1:1；接口和手动生成使用480p，内置videogen按builtin-video.md选择seedance-2.0-fast并在支持时尝试720p，只有用户明确指定其他参数时才调整；时长仍须在模型支持范围内，单条最多15秒。一次请求生成整条画面和声音，不做资产提取，不逐镜分别调用。

## 参考方法

本规则参考novel-vids的 `prompts/storyboard.py`、`prompts/skills/storyboard.md` 和 `prompts/remake_render.py` 中的视频提示词组织方法：将本条初始画面、关键动作、人声及同步声音作为核心内容，镜头内明确动作主体、景别、运镜、时间范围和收尾衔接；摄影术语只在服务画面时使用。

同时参考用户指定的[Seedance 2.0中文提示词技能](https://github.com/dexhunter/seedance2-skill/blob/main/zh/SKILL.md)，采用主体、场景、动作、运镜、时间段、声音与风格的组合表达；有真实输入素材时明确每个引用的作用。这里已经收录本流程需要的方法，不依赖另一个工程才能执行。

只采用适合本任务的写法，不照搬来源中的资产流程、时长、负面清单或字幕限制。当前用户要求与本技能设置优先。

## 先设计这一条视频

1. 从第一步取用事件、人物关系与关键动作；上一阶段暂定的时长、候选分辨率、画幅或声音安排，不覆盖当前所选通道默认和本轮用户要求。
2. 写清初始现场、人物情绪、动作变化、结果和最值得看的瞬间。保持一次完整演绎，不为了填栏目增加无用镜头。
3. 人物只写影响辨识和表演的身份、外观与服装。场景写时间、地点、光照和必要空间关系。仅在动作确实依赖时说明人数、持物手和朝向，不逐人逐手堆机械约束。
4. 安排适合10秒的镜头与节奏。可用2–3个较清楚的时间段组织，不必固定镜头数；镜头之间动作、视线或情绪相接。动作太多先删次要动作，不自动延长到15秒。
5. 按情境安排对白与同期声音。可以自然对话、命令、喊声或简短回应；没有必要时也不强塞台词。旁白一般不需要。历史情境可作合理对白演绎，依据与演绎边界记在制作说明中。
6. 角色首次出现时可配简短姓名、身份或地点介绍，确有辨识价值时才用；有对白就必须有准确同步的字幕。正文不变成旁白，画面字幕也不替代角色表演。

## 模型收到的提示词只描述本条视频

重点写想看到的画面、动作、表情、镜头、对白、字幕与声音，使用具体而自然的表述。不要把拍摄方案写成合规检查表。

画幅、分辨率、最终1080×1920画布、上方文字区、FFmpeg命令、后期拼接和BGM库属于参数或制作记录，不进入模型提示词。尤其不写“不制作最终竖屏版式”“不出现上下分区”等后期说明。

不追加通用“禁止项”段落，不罗列本条没有打算拍的人物、刑场、后续事件或情节，也不一概禁止文字、对白、字幕、人物介绍。内容边界在选材与镜头设计时落实，不靠末尾列一串“不画什么”来补救。源资料没有的情节，不在正文中生成即可。

风格从styles.json的当前项读取，保留本条所需的正面视觉特征。用户IP的身份要求、史料说明、参数限制、输入检查等工作规则不复制到风格正文。不要把整份制作规范粘贴成提示词。

## 推荐组织方式

可采用以下清楚的栏目，也可写成等效的紧凑自然段；不要为了栏目重复同一动作。

```text
【核心画面】
这一幕的初始现场、主要行动、人物情绪及动作结果。

【视觉风格与环境】
本条风格、光照、色彩、实际出场人物的辨识特征和场景要点。

【镜头与动作】
0–3秒：景别、运镜、动作主体和情绪。
3–7秒：主要动作的发展、变化与同步声音。
7–10秒：动作结果、反应与自然收尾。

【对白与画面文字】
有对白时写明时间、角色、精确台词与语气，并写对应字幕；需要人物介绍时写出实际文字及出现时机。没有这类内容时省略本栏。

【声音】
具体的现场环境声、动作声与人声演绎，和动作时间对应。
```

实际交付填入本条完整内容，不保留示意文字或“同上”。必要信息写足，能用一句话说清的不拆成多句限制；不强行套用每一个栏目。

### 对白、字幕与人物介绍

- 每句台词写清谁说、说什么、怎样说、何时说，给足发音和反应时间。
- 同一条有对白的视频，提示词明确要求同步中文字幕，并给出与台词一致的实际字幕原文；字幕在本条视频画面中自然呈现、位置清晰。
- 人物介绍只写有依据的姓名或身份，指定初次亮相时的简短呈现，不把介绍变成整段知识讲解。
- 没有对白或介绍需求时直接省略相应内容，不追加一整段“无对白、无字幕、无文字”等禁令。
- 声音以本条现场环境声、动作声和人物演绎构成。BGM库的选曲与后期混音不属于本条模型提示词内容。

## 可选参考输入

默认references为空，直接提交文本，不创建图片或索取资产。用户明确提供参考时才说明用途；使用 `{{ref:R01}}` 等稳定标记，脚本根据本次真实上传顺序转换为@图片N。每条可选记录保留兼容字段asset_id、实际文件、哈希与role，不建立资产阶段。

## 文件和调用参数

保存《分镜提示词.md》和《分镜提示词.json》。Markdown把“完整模型提示词”与“调用参数／制作说明”分开；JSON的prompt_template只放前者，内容与Markdown一致。

JSON顶层style_id与shots，默认一条视频请求。调用参数示意：

```json
{
  "id": "shot-01",
  "title": "选定精彩片段",
  "duration": 10,
  "ratio": "1:1",
  "resolution": "480p",
  "generate_audio": true,
  "prompt_template": "本条完整的画面、动作、镜头、声音、对白及相应字幕要求。",
  "references": []
}
```

接口和手动方式默认值取自references/qiling-video.json的generation_defaults：duration=10、resolution=480p、ratio=1:1、generate_audio=true。分镜JSON须明确写出这些值，不沿用旧稿的15秒、720p、9:8或ratio=null，也不再用target_ratio代替ratio。只有本轮用户明确指定其他有效值时覆盖相应字段；参数核实、授权、费用与后期安排写在制作说明，不拼入prompt_template。

## 检查与停止点

检查10秒内动作和对白能否完成、镜头是否冲突、字幕是否逐句对应台词、人物介绍是否准确、声音是否同步。再只读模型提示词：是否混入了参数解释、后期拼接、无关情节禁令或重复限制？发现时修正规则执行产生的本次新稿，不能手工修补旧产物冒充验证。

用户只要求提示词时，交付文件并停止，不调用视频接口。正常创作完成提示词后继续获取视频，通过检查后直接进入第三步，不例行要求用户逐阶段确认。用户要求实际生成且有Key时按qiling-video.md提交；无Key时先按builtin-video.md检查真实videogen，默认使用seedance-2.0-fast，支持时尝试720p；选择手动生成时按local-video.md交付可复制提示词与单独的参数说明，等待本地视频。用户已提供本地视频时直接进入导入检查，不因没有API参数或调用号而阻塞。取得视频后检查真实画面、表演、对白和字幕，不因单次生成就宣称已经合格。
