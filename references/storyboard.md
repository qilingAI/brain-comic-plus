# 分镜与视频提示词

这是第二步。读取第一步压缩后的完整故事、核心反转和逐字台词。选择 MiniMax H3（含 AutoDL 的 H3 工作流）时按 [MiniMax 调用](minimax-h3.md) 直接使用同一份已审阅的中文结构提示词。以下通用提示词可用于器灵接口、默认宿主videogen及豆包等手动生成方式。根据剧情和阅读负担在10–15秒内选择时长，默认1:1；接口、手动和内置生成默认720p，MiniMax H3（含AutoDL）默认768p，内置videogen按builtin-video.md选择seedance-2.0-fast，按内容选择时长，其他参数按用户要求调整；时长仍须在模型支持范围内，单条最多15秒。一次请求生成整条画面和声音，不做资产提取，不逐镜分别调用。

## 参考方法

本规则参考novel-vids的 `prompts/storyboard.py`、`prompts/skills/storyboard.md` 和 `prompts/remake_render.py` 中的视频提示词组织方法：将本条初始画面、关键动作、人声及同步声音作为核心内容，镜头内明确动作主体、景别、运镜、时间范围和收尾衔接；摄影术语只在服务画面时使用。

同时参考用户指定的[Seedance 2.0中文提示词技能](https://github.com/dexhunter/seedance2-skill/blob/main/zh/SKILL.md)，采用主体、场景、动作、运镜、时间段、声音与风格的组合表达；有真实输入素材时明确每个引用的作用。这里已经收录本流程需要的方法，不依赖另一个工程才能执行。

只采用适合本任务的写法，不照搬来源中的资产流程、时长、负面清单或字幕限制。当前用户要求与本技能设置优先。

## 先设计这一条视频

连续剧或用户要求完整结构分镜时，先按 [连续剧编排与结构分镜](series-storyboard.md) 保存初始画面、空间关系、动作时间轴、逐句人声与转场，供审阅及模型编译使用。

1. 从第一步取用事件、人物关系与关键动作；上一阶段暂定的时长、候选分辨率、画幅或声音安排，不覆盖当前所选通道默认和本轮用户要求。
2. 写清初始现场、人物情绪、动作变化、结果和最值得看的瞬间。把压缩后故事的起因、关键变化、反转和结果安排进文案、对白与镜头；可用少量切镜和时间跳转连接必要事件，不为填栏目增加无用镜头。
3. 人物只写影响辨识和表演的身份、外观与服装。场景写时间、地点、光照和必要空间关系。仅在动作确实依赖时说明人数、持物手和朝向，不逐人逐手堆机械约束。
4. 安排适合所选时长的镜头与节奏。可用2–3个较清楚的时间段组织，不必固定镜头数；镜头之间动作、视线或情绪相接。10秒演不完时按需要延长，最多15秒；仍过密时删减次要动作。
5. 从故事文稿带入逐字台词，安排到说话人的镜头和同期声音里。自然对话、命令、喊声或回应须能推动故事进展，并按下节要求贯穿全场。旁白一般不需要。历史情境可作合理对白演绎，依据与演绎边界记在制作说明中。
6. 角色首次出现时可配简短姓名、身份或地点介绍，确有辨识价值时才用；有对白就必须有准确同步的字幕。正文不变成旁白，画面字幕也不替代角色表演。

### 志怪动画的节奏与表演

- 开场 1–2 秒让观众看到异常或危险。可将怪物面孔和正在发生的怪事放进同一画面，省去先拍道具、再缓慢抬镜揭晓的等待。留时长给变形、对抗、逃跑等结果真正发生的过程。
- 按国风漫画的表演幅度写惊恐、愤怒或扑击。人物反应可用眼睛睁大、头猛缩、肩背后弹、膝盖一软、急退和转身跑形成连续动作。至少选一个中景也能看清的主动作，给全身反应留足构图空间。若有短暂定格，用在揭晓或受惊的那一拍，随后立刻推进。
- 鬼怪动作写清速度、力量、身体姿态和收势。急抖、猛披、骤停、甩头或伸爪应有可见的起止。变形时写清所有露出部位的最终状态，确认脸、手、服饰是否都随剧情变化。
- 检查每个时间段是否改变局面。细小动作和内心声在需要时补充反应，主要情绪由观众能直接看懂的表演承担。人声短而具体，同步呼吸、衣摆、脚步和碰撞声加强动作。
- 两人隔门或隔窗互动时，先选定机位在哪一侧，说明门窗初始开合状态、出入路径和谁实际可见。每段动作直接写角色名及衣色。空间或主体变化需要切镜时标出切点，狭窄画面也可只拍行动者，让另一个人从画外说话。破坏道具前写清悬挂或持握位置，破坏后交代落点。夸张反应建立在清楚的主体和因果上。

## 模型收到的提示词只描述本条视频

重点写想看到的画面、动作、表情、镜头、对白、字幕与声音，使用具体而自然的表述。不要把拍摄方案写成合规检查表。

画幅、分辨率、最终1080×1920画布、上方文字区、FFmpeg命令、后期拼接和BGM库属于参数或制作记录，不进入模型提示词。尤其不写“不制作最终竖屏版式”“不出现上下分区”等后期说明。

不追加通用“禁止项”段落，不罗列本条没有打算拍的人物、刑场、后续事件或情节，也不一概禁止文字、对白、字幕、人物介绍。内容边界在选材与镜头设计时落实，不靠末尾列一串“不画什么”来补救。源资料没有的情节，不在正文中生成即可。

风格从styles.json的当前项读取，保留本条所需的正面视觉特征。用户IP的身份要求、史料说明、参数限制、输入检查等工作规则不复制到风格正文。不要把整份制作规范粘贴成提示词。

## 推荐组织方式

器灵和 Seedance 使用本节通用组织方式及模型同步生成字幕。MiniMax H3 才按其调用文档的“镜头、台词与字幕绑定”执行专项处理，不将该处理推广到其他通道。

可采用以下清楚的栏目，也可写成等效的紧凑自然段；不要为了栏目重复同一动作。

```text
【核心画面】
压缩后故事的起始处境、关键行动、核心反转与结果。

【视觉风格与环境】
本条风格、光照、色彩、实际出场人物的辨识特征和场景要点。

【镜头与动作】
0–3秒：景别、运镜、动作主体和情绪。
3–7秒：主要动作的发展、变化与同步声音。
7–10秒：动作结果、反应与自然收尾（此为10秒示例，应按实际时长调整）。

【对白与画面文字】
按开场、中段推进、收尾逐句写明起止时间、说话角色、听者、精确台词与语气，并写对应底部同步字幕；与动作时间轴对应。需要人物介绍时写出实际文字及出现时机。

【声音】
仅保留角色对白、动作音效和现场环境声，声音与动作同步。不生成背景音乐或配乐。
```

实际交付填入本条完整内容，不保留示意文字或“同上”。必要信息写足，能用一句话说清的不拆成多句限制；不强行套用每一个栏目。

### 对白贯穿全场

- 每条动画必须以角色开口的表演贯穿开场、中段推进和收尾，连续剧逐集执行；用户明确要求无对白时才例外。开场即进入对话或呼喊，动作发展时继续接话，结尾用回应、决定或反应台词承接结果，不能中途说完全部台词后留一大段展示画面。
- 以自然短句和有来有回的交流推动事件，句数随时长与剧情确定。每句改变信息、情绪或行动，不用重复感叹、无意义喊叫或照读顶部文字填满声音。旁白、内心OS、字幕和音效不能充当角色开口对白。
- 将每句起止时间与动作写在同一时间轴上，覆盖开场、中段和收尾。允许呼吸、接话、反应和动作重音所需的短暂停顿；不追求每秒塞满词句，不重叠抢话或加速念稿。时长不足先精简台词及次要动作，保留贯穿全场的交流。
- 说话时安排能辨认该角色脸部与口型的画面，并写出听者的即时反应；动作与说话可同时进行，避免全片站桩说话。剧情需要的短暂画外回应可保留，但不能全程让人物闭嘴、由画外配音代讲。

### 对白、字幕与人物介绍

- 每句台词写清谁说、说什么、怎样说、何时说，给足发音和反应时间。
- 每句对白都写「画面底部出现字幕，字幕内容为“……”，字幕需与音频节奏完全同步。」把省略号换成该句原文，对齐该句的开口、停顿及结束。每次只显示对应当前人声的字幕。
- 人物介绍只写有依据的姓名或身份，指定初次亮相时的简短呈现，不把介绍变成整段知识讲解。
- 人物介绍按需省略；对白及对应字幕是必需内容，仅用户明确要求无对白时省略。
- 通用提示词在声音段明确写明仅生成角色对白、动作音效和现场环境声，不生成BGM。保留同期声音设置；背景音乐只在合成时添加，选曲和混音信息另存制作记录。选用 MiniMax H3 时同样直接使用这些中文声音要求。

## 可选参考输入

默认references为空，直接提交文本，不创建图片或索取资产。用户明确提供参考时才说明用途；使用 `{{ref:R01}}` 等稳定标记，脚本根据本次真实上传顺序转换为@图片N。每条可选记录保留兼容字段asset_id、实际文件、哈希与role，不建立资产阶段。

## 文件和调用参数

保存《分镜提示词.md》和《分镜提示词.json》。Markdown把“完整模型提示词”与“调用参数／制作说明”分开；JSON的prompt_template只放前者，内容与Markdown一致。

JSON顶层style_id与shots，默认一条视频请求。调用参数示意：

```json
{
  "id": "shot-01",
  "title": "压缩故事与核心反转",
  "duration": 10,
  "ratio": "1:1",
  "resolution": "720p",
  "generate_audio": true,
  "prompt_template": "本条完整的画面、动作、镜头、声音、对白及相应字幕要求。",
  "references": []
}
```

接口和手动方式默认值取自references/qiling-video.json的generation_defaults：resolution=720p、ratio=1:1、generate_audio=true；duration根据剧情选择并明确填写。分镜JSON须明确写出这些值，不自动沿用旧稿的时长、480p、9:8或ratio=null，也不再用target_ratio代替ratio。用户明确指定的有效参数优先；参数核实、授权、费用与后期安排写在制作说明，不拼入prompt_template。

## 检查与停止点

先检查压缩后的故事是否保留必要因果、核心反转和结果，再沿时间轴检查开场、中段推进、收尾是否均有角色开口，是否出现整段纯展示或以旁白代替对白，再检查所选时长内动作和对白能否自然完成、镜头是否冲突、字幕是否逐句对应台词、人物介绍是否准确、声音是否同步。再只读模型提示词：是否混入了参数解释、后期拼接、无关情节禁令或重复限制？发现时修正规则执行产生的本次新稿，不能手工修补旧产物冒充验证。

用户只要求提示词时，交付文件并停止，不调用视频接口。正常创作完成提示词后继续获取视频，通过检查后直接进入第三步，不例行要求用户逐阶段确认。用户要求实际生成且有Key时按qiling-video.md提交；无Key时先按builtin-video.md检查真实videogen，默认使用seedance-2.0-fast，默认720p；选择手动生成时按local-video.md交付可复制提示词与单独的参数说明，等待本地视频。用户已提供本地视频时直接进入导入检查，不因没有API参数或调用号而阻塞。取得视频后检查真实画面、表演、对白和字幕，不因单次生成就宣称已经合格。
